制御事業者に必要な5つのセキュリティ領域
- 情報システム
  パソコン端末、モバイル端末、Web、メール、アプリケーションサーバなど、基本的にインターネット接続している国内外のシステム
- 制御システム
  国内外の工場・プラントの操業（そうぎょう）を行う制御システム
- 製品・サービス
  顧客に提供するサイバー的な要素を含む製品・サービス
- サプライチェーン上流
  １）２）のシステム、３）製品・サービスのための自組織外のサプライヤー及び、調達される製品・サービス
- サプライチェーン下流
  ３）製品・サービスを提供する顧客及び製品・サービスが使用される顧客環境

4P対策
- 組織（People）
  社員啓発（けいはつ）・教育・サーバー演習、専門職採用、CSIRT、SOC、製品SIRT、経営層啓発など組織・人の強化にかかわる施策
- 運営（Process）
  規制・コンプライアンス対応、セキュリティリスク評価、社員管理、ID管理、アプリケーション管理、脆弱性管理、ポリシー・ルール策定・更新管理、サイバーセキュリティに起因するBCP策定・更新管理など、組織や人の運用にかかわる施策
- システム（Products）
  アンチウィルスなどの端末、ネットワークセキュリティ・ログ監視などの製品/ソリューション・サービス・技術にかかわる施策
- パートナー（Partners）
  コンサルティング会社、MSSP（Managed Security Service Provider：セキュリティ監視のアウトソーシングを提供する事業者）、セキュリティベンダー、製品機器ベンダー、セキュリティ教育・資格プロバイダー、サイバー保険会社など自社のセキュリティ対策に活用できる外部リソース


セキュリティ対策におけるビジネス視点整理

| ビジネス視点項目 | 内容説明                                                                                              |
| -------- | ------------------------------------------------------------------------------------------------- |
| ビジネス目標   | 製造事業者がビジネスを行ううえでの達成すべき目標。経営レベルであれば売上・利益目標、業界での位置づけなどがあがられる。                                       |
| ビジネス戦略   | ビジネス目標を達成するため、ための大方針。経営レベルであれば、経費削減、ITへの積極的な投資、M&A、事業部門のカンパニー化・子会社化、不採算部門売却などがあげられる。              |
| プロジェクト   | ビジネス戦略に従い、ビジネス目標を達成するための施策。例えば、「社内システムのO365移行」などの具体的なビジネス施策のこと。                                   |
| 想定リスク    | 対象ビジネス領域に想定されるセキュリティリスクのこと、「プロジェクト」によって新たに生まれるリスクも含む。                                             |
| 法規制      | 対象ビジネス領域に関連する国内外の法規制。遵守（じゅんしゅ）以外の選択肢がないので、リスクとは別に分けて記載している。                                       |
| 守るべきもの   | 対象ビジネス領域において、想定リスクを考慮したうえで、セキュリティ対策を行って守るべきもの。必ずしも、顧客データのような実体のあるものではなく、工場の安定稼働や、ビジネス機会のようなものも含む。 |

情報システムのビジネス視点整理

| ビジネス視点 | 例                                                                                                                                  |
| ------ | ---------------------------------------------------------------------------------------------------------------------------------- |
| ビジネス目標 | 情報システム全体のTCO削減、働き方改革による労務管理改善、海外拠点ガバナンス強化、DX推進による社内文化改革                                                                            |
| ビジネス戦略 | オンプレミスからクラウドへの移行、BYODの推進、テレワーク推進、紙管理からオンライト化、業務管理の自動化・省力化                                                                          |
| プロジェクト | 社内システムのSaaS移行（O365、Salesforce、SAP、Slack、Dropboxなど）、オンライン会議システム導入、社内ポータル拡充（労務管理のオンライン化など）、RPAなど活用した社内申請処理の自動化                       |
| 想定リスク  | マルウェア感染、内部不正、操作/設定ミスなどに起因する情報漏えいによる法令違反・訴訟（そしょう）の発生及び営業競争力の低下。ランサムウェア感染などによる業務停止・ビジネス機会損失・顧客対応サービスの低下。攻撃者の踏み台化による間接的な他社（顧客）・個人への攻撃 |
| 法規制    | 個人情報保護法、EUのGDPR、中国サイバーセキュリティ法など各国の個人情報、データローカリゼーションにかかわる規制                                                                         |
| 守るべきもの | 個人情報（社内・取引先）、重要情報（営業秘密・知財など）、事業継続、DXによる変革された社内文化                                                                                   |

クラウドへの移行の利点とリスク
- 「責任共有モデル」
- SaaS利用で、GDPRや各国のデータ保護規制を遵守する

4P対策
People
SaaS移行のPJは、経営企画や情シスが中心となって、セキュリティの検討まで「手が回らない」
１）人材不足と考慮漏れ
製造事業者内にセキュリティ専任の人材は少ない
既存PJ保守、インシデント対応で、新PJへの参画が遅れてしまう。
企画・設計段階でのセキュリティ考慮漏れ　⇒　Security by Design思路
供应商例会上就要考虑到这一点
２）長期的な視野に立ったセキュリティ中核人材の育成
対策の中心となる人を必要な人数アサインして数年後戦力となるように投資しましょうという意味です。
３）PJ担当部門にセキュリティ責任者を置く
この責任者は必ずしもセキュリティに詳しい技術者である必要はない。PJの全フェーズにおいてセキュリティ対策が十分かどうかを検討することである。
事先划分责任，事业部自己的判断因为预算不足导致安全对策不充分，主体责任要列清楚。

Process
どんなに高価なセキュリティ対策製品を導入しても、設定が間違っていれば意味がないこと
